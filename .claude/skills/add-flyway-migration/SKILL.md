# Flyway 마이그레이션 추가

스키마는 Flyway로만 변경한다. `ddl-auto`는 `validate`이므로 엔티티와 DDL이 어긋나면 애플리케이션이 기동하지 않는다.

## 1. 버전 번호 확인

```bash
ls src/main/resources/db/migration/
```

- 가장 큰 `V{n}`을 찾고 `V{n+1}`을 사용한다. 번호를 건너뛰거나 재사용하지 않는다.
- 파일명: `V{n}__{snake_case_설명}.sql` (언더스코어 **두 개**). 예: `V3__add_category_to_posts.sql`

## 2. 절대 규칙

- **이미 존재하는 마이그레이션 파일은 수정하지 않는다.** 내용이 틀렸어도 새 버전으로 고친다 (checksum 불일치로 기동 실패).
- 한 파일에는 하나의 논리적 변경만 담는다.
- `DROP TABLE`, `DROP COLUMN`, 컬럼 타입 축소처럼 데이터가 사라지는 변경은 **작성 전에 사용자에게 확인**한다.

## 3. DDL 작성 규칙

| 항목 | 규칙 |
|------|------|
| 테이블명 | 복수형 snake_case (`posts`, `comments`) |
| 컬럼명 | snake_case. 엔티티 필드 camelCase와 Hibernate 기본 naming 전략으로 매핑 |
| PK | `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` |
| 문자열 | 길이 제한 있으면 `VARCHAR(n)`, 본문은 `TEXT` |
| 시각 | `TIMESTAMPTZ NOT NULL` |
| FK | `REFERENCES {table} (id)` + 삭제 정책 명시 (`ON DELETE CASCADE` 등) |
| 인덱스 | `idx_{table}_{columns}`. FK 컬럼, 조회 조건/정렬 컬럼에 생성 |
| 제약조건 이름 | `fk_{table}_{ref}`, `uk_{table}_{columns}` |

### NOT NULL 컬럼을 기존 테이블에 추가할 때

데이터가 있는 테이블에 바로 `NOT NULL`을 추가하면 실패한다. 순서:

```sql
ALTER TABLE posts ADD COLUMN category VARCHAR(30);
UPDATE posts SET category = 'GENERAL' WHERE category IS NULL;
ALTER TABLE posts ALTER COLUMN category SET NOT NULL;
```

## 4. 엔티티 동기화

- 같은 작업에서 엔티티의 `@Column(length, nullable)`, `columnDefinition`을 DDL과 일치시킨다.
- `@Lob` 금지 (PostgreSQL에서 `oid`로 매핑됨). 긴 문자열은 `columnDefinition = "text"`.
- 연관관계 FK에 `ON DELETE CASCADE`를 썼다면 엔티티에도 `@OnDelete(action = OnDeleteAction.CASCADE)`.

## 5. 검증

1. `./gradlew test` — Testcontainers 기반 테스트가 Flyway를 실제로 실행하고 `validate`까지 통과해야 한다.
2. 실패 메시지가 `Schema-validation: missing column` / `wrong column type`이면 엔티티와 DDL 불일치다. **이미 커밋된 파일은 고치지 말고**, 아직 커밋 전인 이번 파일만 고친다.

## 6. 문서 갱신

- `docs/domain-model.md`의 ERD, 타입 매핑, 마이그레이션 섹션을 갱신한다.
- 엔티티 변경과 마이그레이션 파일은 같은 커밋에 포함한다.
